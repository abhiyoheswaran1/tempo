# Stored-band history and gaps

Live receipt and stored-history transfer are separate capabilities. A worn band and current HR do not prove that earlier readings reached the phone or were stored in band flash. No invented samples or interpolation fill chart gaps.

WHOOP4: subscribe to documented custom channels, confirmed battery query, then application-version query7. Only a successful68-byte revision1 application reply reporting41.17.6.0 enables experimental command22/body00. Standard DIS firmware alone never enables it. START/END/COMPLETE and v24/v25 remain different records. Per-channel bounded reassembly rejects discarded bytes before any ACK; END with unresolved bytes on any subscribed channel is rejected conservatively rather than acknowledging an omitted partial frame. Unknown sensor layouts remain raw, never guessed metrics. The experimental v24 zero-contact flag preserves the measured value but excludes it from analytics; it is not promoted to verified off-body status. This prevents an uncertain charging-band reading filling a worn band’s gap.

A chunk holds at most2MiB/10,000frames. Its decoded observations, rejected-layout frames, all raw frames and original8-byte token commit atomically with FULL/WAL durability. Chunk decoding runs off the main actor; storage remains actor-owned. Recent backfill is labelled recent, never a live stream. Ordinary command23 receipt ACK uses01 plus that exact token only after commit, scoped to the same connection/session/dataset. This can permit reclamation of copied band data; forced trim/erase/reset commands are excluded. Empty/incomplete/special-token/damaged chunks cannot be acknowledged. Retries retain IDs; duplicate END handling only acknowledges an already committed token. COMPLETE does not commit an open chunk or prove gap-free coverage.

Each connection reads metadata once; supported W4 retrieval starts automatically after version confirmation and retries on foreground/live snapshot checks when15minutes old. Manual refresh requests a fresh attempt unless one is active. Transfers stop locally after120seconds; a bounded abort20 does not trim uncommitted data. Background wakeups remain subject to iOS. A finite background assertion protects chunk storage, not continuous execution. Force-quit and unvalidated firmware can leave gaps. Reconnect replay and oldest retained date require physical testing. A connection uses at most250 command sequences before reconnect is needed, avoiding unproven sequence-wrap reuse.

WHOOP5: subscribed custom channels and documented Hello145 inspect application firmware. On50.42.1.0, range34 is read-only; its65-byte body reports an estimate, not a retention duration or proof of recovered measurements. No range refusal/timeout/zero estimate is presented as recovered history. This adapter does not invent W5 metadata offsets or reuse W4 layouts. Current [Noop12.0 report](https://github.com/ryanbr/noop/releases/tag/v12.0.0) describes independent pairing failures leaving some bands un-clocked, not storing flash data and offloading empty. This is community evidence, not diagnosis of the owner's band. No authentication bypass, service account, certificate transfer or firmware change is attempted.

Test procedure: update Tempo; open Today → band status, then inspect application firmware/history status. For W4 supported firmware, let a transfer finish, compare receipt timestamps against persisted history, disconnect briefly, reconnect and verify actual recovered records without duplicate activity. For W5, report Hello/range status and application firmware first. A physical gap-recovery result is still required before this is daily-use ready. Personal captures stay private.
