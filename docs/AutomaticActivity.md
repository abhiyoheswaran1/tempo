# Automatic activity detection — implementation brief

Tempo detects **potential workouts**, then ask the user to confirm activity type and timing. This is an original experimental heart-rate-only rule, not WHOOP's activity classifier. It cannot identify padel or distinguish exercise from stress, illness or other causes of elevated HR.

Defaults: opt-in/off initially; start requires two consecutive qualifying minutes with HR >=65% of configured maximum; qualifying minutes need >=80% measured coverage and >=70% of covered time above threshold. Sustain uses >=55% maximum for >=50% of covered time. Minimum duration10minutes. Finish after3minutes below sustain; missing/insufficient coverage splits a session and is disclosed. Adjacent measured samples at most10seconds apart define covered exposure; no fill across larger gaps. The final incomplete minute is not evaluated as absence.

Only accepted directly measured band HR is eligible in real mode. Imported Health records, off-body/invalid values and synthetic observations are excluded. Canonical source selection prevents overlapping devices from increasing exposure. A supported source switch can retain one candidate. Manual/imported workouts suppress overlapping proposals. Dismissal/confirmation persists as revision ancestry; deterministic candidate/workout IDs prevent repeated scans or restored installations from duplicating the same proposal. Candidates do not count as workouts or get exported to Health until explicitly confirmed. Completed confirmed estimates may be exported with user-entered and Tempo estimate provenance when workout export is enabled; synthetic and imported sessions remain excluded. Demo detection requires an explicit isolated demo store and flag. Synthetic workout and candidate revisions are rejected from real stores, including archive imports.

The service analyzes bounded recent stored data on activation/manual scan and periodically when live samples arrive. It does not add a background timer or promise collection after force-quit. It cannot recover uncollected history. Algorithm version and source coverage/digest are retained. Changing thresholds does not silently rewrite confirmed/manual sessions.

Implementation: pure core detector + revision-backed proposals/decisions + Activity review editor + opt-in settings + tests for sustained HR, short elevations, missing/invalid data, duplicate/overlap records, source switches, suppression and replay. Physical detection accuracy remains unvalidated.
